# vault-loop

Phone note → Plane ticket → Claude Code on the PC → PR → lesson back in the vault.

This repo holds the infrastructure for that loop. The plan and roadmap live in
the artifact "Vault-to-PR Loop"; `docs/PHASE0.md` is the step-by-step for the
first phase.

## Shape

| Piece | Where | What |
| --- | --- | --- |
| Vault sync peer | CT 107 `syncthing` (existing, eiyan2) | Always-on Syncthing copy of the vault |
| Control | CT `vault-loop` (new, eiyan2) | n8n: queue, triggers, Run now page |
| Tickets + roadmaps | CT `plane` (eiyan2) | Plane Community, from the Proxmox VE community script (not this repo) |
| AI work | The Windows PC | Claude Code under the existing subscription |
| Capture | Phone + PC | Obsidian, Syncthing |

Nothing in the lab is published to the internet in Phase 0. The phone reaches
n8n and Plane over Tailscale, through the existing subnet route.

## Layout

```
proxmox/create-lxc.sh          host: create CT vault-loop (--role loop)
proxmox/update-lxc.sh          host: re-run the n8n installer inside it
proxmox/setup-vault-backup.sh  host: nightly git backup of the vault in CT 107
install/loop.sh                inside CT vault-loop: Docker + n8n
pc/check-pc.ps1                PC: read-only check of the PC prerequisites
pc/new-vault.ps1               PC: create the vault folder skeleton
n8n/src/workflow.js            source of the loop's single n8n workflow (edit this)
n8n/workflows/vault-loop.json  generated by n8n/build.sh (import this)
n8n/setup-n8n.sh               creates the queue table + credentials, imports and activates the workflow
vault/Templates/               note templates: CHANGE, PROJECT, INCIDENT, IDEA
vault/Systems/                 the systems registry, one note per system
docs/ENDPOINTS.md              every address, webhook, API key and token: what for, and where it lives
docs/PHASE0.md                 the Phase 0 runbook
docs/PHASE1.md                 Phase 1: templates, registry, Plane projects and states
docs/PHASE2.md                 Phase 2: triggers, queue, Run now, the worker API
docs/N8N.md                    n8n: the two ways to install, web interface vs .env, workflows in git
docs/PLANE.md                  Plane (community script): one workspace, a project per system, webhooks to n8n
test/run-scripts.sh            script tests, Docker only
```
