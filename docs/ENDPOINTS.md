# Addresses, keys and webhooks

Every address, API key, token and webhook the loop uses: what it is for and
where it lives. **No secret values are written here or anywhere in this repo**;
each row says where the real value is kept. Update this file in the same change
whenever an address, key or webhook is added, moved or removed.

`<loop-ip>` and `<plane-ip>` are placeholders until those containers have their
addresses; fill them in here once they do.

## Addresses

All on the home LAN, `192.168.0.0/24`. The phone reaches them over Tailscale
through the subnet route the `homarr` node advertises. Nothing here is exposed
to the internet.

| Address | What | Used for |
|---|---|---|
| `192.168.0.36:8384` | CT 107, Syncthing (eiyan2) | Vault sync hub. Web UI, and the REST API n8n polls for sync events |

## Webhooks and HTTP endpoints

| Endpoint | Caller → receiver | Auth | Purpose |
|---|---|---|---|
| `POST http://<loop-ip>:5678/webhook/vault-loop/plane` | Plane → n8n | LAN only; Plane may only send to n8n's address (`WEBHOOK_ALLOWED_IPS`) | Work item events; an item moved to **Approved** queues a job |
| `GET/POST http://<loop-ip>:5678/form/vault-loop/run-now` | You (phone/PC) → n8n | LAN / Tailscale only | Run now form: scan Inbox, process one note, retry a failed job |
| `POST http://<loop-ip>:5678/webhook/vault-loop/jobs/next` | PC worker → n8n | header `X-Worker-Token` | Claim the oldest queued job |
| `POST http://<loop-ip>:5678/webhook/vault-loop/jobs/report` | PC worker → n8n | header `X-Worker-Token` | Report a job `done` or `failed` |
| `GET http://<loop-ip>:5678/metrics` | CT 200 / CT 201 → n8n | none (LAN) | Prometheus metrics |
| `GET http://<loop-ip>:5678/healthz/readiness` | installer → n8n | none | Readiness check during install |
| `GET http://192.168.0.36:8384/rest/events` | n8n → Syncthing (every minute) | header `X-API-Key` | Which notes CT 107 received, and when the folder is idle |
| `http://<loop-ip>:5678/api/v1/...` | `n8n/setup-n8n.sh` → n8n | header `X-N8N-API-KEY` | Creates the queue table, credentials and workflow |

GitHub is **polled**, never a webhook: GitHub's servers can't reach the LAN.

## Keys, tokens and secrets

| Secret | Where the value lives | Used by | Notes |
|---|---|---|---|
| n8n API key | Created in n8n: *Settings → n8n API*. Not stored by the repo | `n8n/setup-n8n.sh`, passed as `N8N_API_KEY` | Only needed when running setup; delete it in n8n afterwards if you like |
| `N8N_ENCRYPTION_KEY` | CT 110: `/opt/vault-loop/.env` (mode 600) | n8n, to encrypt saved credentials | **Back it up.** Without it, credentials saved in n8n are lost on a rebuild |
| Worker token | CT 110: the `TOKEN_FILE` setup wrote (e.g. `/root/worker-token`, mode 600), and n8n credential **"vault-loop worker"** | PC worker, header `X-Worker-Token` | Generated by setup on first run. Copy it to the PC worker in Phase 3 |
| Syncthing API key | CT 107's Syncthing: *Actions → Settings → General*. Copied into n8n credential **"Syncthing CT 107"** | n8n's Syncthing poll, header `X-API-Key` | Passed to setup once as `SYNCTHING_API_KEY` |
| Plane admin credentials | Plane CT: `~/plane.creds` (written by the community script) | You, for `/god-mode/` | |
| Plane bot account API token | Created under the bot account in Plane (Phase 1) | PC worker (Phase 3) | Bot is a member of the `homelab` workspace only |
| Plane webhook secret | Shown by Plane when the webhook is created | Not used yet | Kept for when signature checks are added |
| Vault backup deploy key | CT 107: `/var/lib/vault-backup/id_ed25519`; the public half is a deploy key on the private vault repo | `vault-backup` timer, push over SSH to GitHub | Write access to that one repo only |
| Claude Code token | PC: `claude setup-token` (Phase 3) | PC worker | Under the existing subscription |
